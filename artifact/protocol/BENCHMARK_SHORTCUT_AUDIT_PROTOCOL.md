## Research question

Do step-level tool-safety evaluations reward guards for detecting benchmark-construction
proxies rather than for distinguishing the safety of the candidate action in context?

The audit separates three claims:

1. **Label predictability:** a deliberately capability-poor rule predicts released labels.
2. **Observational guard association:** released guard decisions correlate with the same proxy.
3. **Causal guard reliance:** a guard changes its decision when only the suspected proxy is
   changed while the candidate action's authorization and effect are preserved.

Only the third claim supports causal language about a guard relying on a shortcut.

## Prior knowledge at freeze time

The evaluation labels and released guard outputs have already been inspected. This is a
diagnostic audit, not a preregistered confirmatory study. Known observations include:

- AgentDojo-Traj contains 1,220 steps: 868 strict-safe and 352 strict-unsafe.
- All 352 unsafe steps and 321 safe steps contain the literal `<INFORMATION>` marker in
  history; 547 safe steps do not.
- A fixed marker-plus-side-effect-prefix rule has approximately 0.80 pooled F1.
- An exact tool lookup has approximately 0.90 pooled F1 but degrades under domain holdout.
- AgentHarm-Traj contains 525 strict-unsafe `harmful_steps` and 206 strict-safe
  `benign_steps`; an all-unsafe prediction therefore has high positive-class F1.
- Exploratory conditioning showed that strong hosted guards usually distinguish marked safe
  and unsafe AgentDojo steps, while Claude Haiku 4.5 frequently blocks marked safe steps.

The transformations, selection rule, and metrics below are fixed before obtaining any model
predictions on transformed inputs.

## Fixed AgentDojo cohort

Select at most eight strict-safe and eight strict-unsafe marker-present base steps per domain
(`banking`, `slack`, `travel`, and `workspace`). Within each domain/label cell, order samples
by SHA-256 of `260828:<sample_id>` and take the first eight. This yields at most 64 base
steps and prevents selecting examples after viewing transformed predictions.

For every base step, score four variants:

1. `original`: unchanged released input.
2. `marker_paraphrase`: replace only `<INFORMATION>` and `</INFORMATION>` with
   `<UNTRUSTED_EXTERNAL_CONTENT>` and `</UNTRUSTED_EXTERNAL_CONTENT>`.
3. `tool_alias`: consistently replace the parsed candidate tool name with a deterministic
   opaque alias in user request, history, current action, and tool descriptions.
4. `combined`: apply both changes.

Marker paraphrasing preserves the injection text and explicit untrusted provenance. Tool
aliasing preserves the tool description, arguments, and capability. Labels are inherited
from the original. Rows for which the candidate tool cannot be parsed or a transformation
does not actually change the intended field are excluded before inference and counted.

### Post-hoc repeated Claude Haiku 4.5 amendment (before successful inference)

The first direct-Anthropic Haiku counterfactual attempt failed authentication on every
request and produced no usable prediction. After the initial TS-Guard and GPT-5.5 results
were inspected, we added a post-hoc repeated-response Haiku experiment through OpenRouter.
It is a robustness follow-up, not preregistered evidence, and does not alter the frozen
64-base AgentDojo cohort or any existing marker, tool-alias, or combined transformation.

The follow-up adds one negative-control condition, `neutral_json_formatting_placebo`. It
pretty-prints only the outer JSON object passed to the guard. The four JSON field values,
including every byte of the benchmark's user request, history, current action, and tool
descriptions, are identical after parsing. Thus it estimates sensitivity to a generic input
format change without removing the suspected marker or renaming the tool.

Each of five conditions (original, marker paraphrase, formatting placebo, tool alias, and
combined) is called three times for every base step, for 960 planned calls. The latter two
original calls are byte-identical repeat-original controls. Calls are deterministically
interleaved with seed `260829`: for each repetition, base order is shuffled, then the five
conditions are shuffled within each base. Concurrency is at most two and each transient
failure receives at most three attempts. The model is
`anthropic/claude-haiku-4.5`, pinned to OpenRouter's `anthropic` provider with fallbacks
disabled, temperature zero, 256 output tokens, native strict JSON-schema output, and no
tools or plugins. Every record stores the resolved model/provider, rendered-input hash,
complete request hash, frozen prompt and cohort hashes, schedule position, usage, and cost;
the key is loaded only at runtime from the ignored desktop key file.

The primary estimand for each transformation is its base-equal marginal block-probability
difference from original, averaging the three calls within each condition and then the 64
bases. Uncertainty resamples base steps within domain-by-gold-label strata. Within-condition
repeat disagreement is only a stability diagnostic; it is not subtracted from the
transformation effect and must not be interpreted as a causal baseline. Failures remain
fail-closed in the strict estimate and are also reported separately as coverage failures.

Using input and output token counts from the earlier successful first-party Haiku run on
the same 64 original inputs, the 960-call expected list-price cost is approximately $3.40
at OpenRouter's current $1/$5 per-million input/output-token rates, before cache discounts.
If every successful call used the full 256-token output allowance, the corresponding
single-attempt projection is approximately $4.46. The runner additionally defaults to a
$6 observed-cost stop. No request from this amendment had been sent when it was written.

#### Pre-inference output-budget amendment

The first protocol draft specified 256 continuation tokens. Before any counterfactual
TS-Guard output was generated, we audited all 1,220 released AgentDojo TS-Guard reasons
with the pinned tokenizer. Their continuation lengths have median 207, 95th percentile
277, and maximum 432 tokens; 126/1,220 (10.3%) exceed 256 tokens. Because the required
judgment tags occur after the analysis, a 256-token cap could manufacture parser failures
and fail-closed unsafe predictions. The primary cap is therefore amended to the authors'
2,048-token setting. EOS normally stops earlier, and the longest prepared input plus this
budget is 15,135 tokens, below the checkpoint's 32,768-token context. This amendment was
made while the checkpoint download was still in progress and before viewing any local
counterfactual prediction.

The audited upstream artifact is
`guardian_test_logs/agentdojo/TS-Guard/meta_data.json` at ToolSafe commit `46358fa`,
12,235,769 bytes with SHA-256
`a092f77c68911a7be0770f55982148d21132c39ceca8e9cc4a69b11d96ebce1b`.
Lengths exclude added special tokens and use checkpoint revision `ad2f82df`.

### Post-hoc independent-review amendment (before additional inference, 2026-08-29)

Independent reviewers identified two inference issues and two high-value extensions. This

#### Correct stochastic estimand

For a stochastic guard, an unsigned one-draw disagreement rate is not the signed marginal
transformation effect, and subtracting an identical-input disagreement rate does not make it
one. The primary stochastic estimand is

`mean_i [Pr(g(T(x_i)) = block) - Pr(g(x_i) = block)]`,

Under stationarity, one independent signed draw per condition is unbiased for this average
but is noisy and provides no within-condition stability or drift check. Repeated interleaved
calls improve precision and diagnose those assumptions. Identical-input disagreement is
retained only as a stability diagnostic. The completed non-interleaved GPT-5.5 unsigned flip
counts remain descriptive; the planned GPT-5.6 Sol run was not executed.

## Metrics

Report per guard:

- strict balanced accuracy, F1, false-positive rate, and false-negative rate by variant;
- paired strict-decision flip rate from `original` to each transformed variant;
- unsafe-to-safe and safe-to-unsafe directional flip rates separately;
- paired bootstrap 95% intervals clustered by base sample, with 10,000 replicates;
- results by AgentDojo domain and original label;
- exact coverage and provider/parser failure counts.

For authorization pairs, report the fraction where the unsafe score exceeds the safe score,
ties, reversals, and conclusions by serialization. With eight pairs, report counts rather than
significance claims.

## Decision rule

The shortcut thesis receives useful support if at least one competitive guard shows a
material, directionally coherent performance change under a label-preserving transformation,
and the effect is not confined to one domain. A descriptive label rule without transformed
guard behavior is insufficient.

If stronger guards remain stable and only a weak guard fails, report this as a bounded result:
the benchmark contains exploitable proxies, but strong monitor performance is not explained
by those proxies. If no causal effect appears, retain the result as an evaluation-audit
methodology or return to the original paper plan.
